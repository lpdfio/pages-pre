Factur-X / ZUGFeRD invoices

A Factur-X invoice, called ZUGFeRD in Germany, is one PDF that holds an invoice twice: as pages people read, and as XML that accounting software reads. France and Germany accept it as an electronic invoice.

Your accounting software, or an e-invoice library, already writes the XML. These guides turn it into the PDF with a template for the look and one call. The pages are read from the XML, so the two cannot disagree.

What each guide covers

Section titled “What each guide covers”
  1. Write the template: how the invoice looks, with values taken from the XML.
  2. Make the PDF: one call that fills the template, embeds the font, writes the file as PDF/A-3 and attaches the XML.
  3. Check the result with the Mustang CLI, an open-source Factur-X checker.
  4. What to do when it fails: the errors a first invoice usually meets.

What Lpdf does, and what is yours

Section titled “What Lpdf does, and what is yours”

Lpdf reads the XML, fills the template, writes the file as PDF/A-3, attaches the XML and writes the Factur-X metadata that names its profile. It does not write the XML, and it does not check the XML’s content against the rules of EN 16931: check the XML your software writes with the Mustang CLI or the KoSIT validator before you rely on it.
